## 2024-05-15 - [Path Traversal in Export Operations]
**Vulnerability:** Methods that export files (like `ConsentRepositoryImpl.exportAuditLog`) were constructing a `File` object directly from user-provided input strings without checking the resulting path.
**Learning:** Repositories handling exports might neglect path validation if the export destination is passed in as a string. Even if the path *looks* like an absolute path, it might contain `../` segments that break out of the intended directory.
**Prevention:** To prevent path traversal vulnerabilities during file generation (like exports), always resolve the `canonicalPath` of user-provided paths and verify they match an allowed base directory exactly (`canonicalPath == base`) or strictly begin with the directory plus a separator (`canonicalPath.startsWith(base + File.separator)`) to prevent partial-directory bypasses (e.g., `/files-spoofed`). Do not pass unsanitized paths directly to `File()`. Use a centralized validation function like `getSafeFile`.
