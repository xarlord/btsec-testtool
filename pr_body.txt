💡 What:
- Added stable `key` parameters to `LazyColumn` `items()` calls across the application (Scanner, VulnScanner, Fuzzer, and KeyExtraction screens).
- Fixed CI pipeline configuration to use explicit flavor tasks (`app:assembleDevDebug`, `app:testDevDebugUnitTest`, `app:lintDevDebug`) and added `--no-configuration-cache` for the OWASP Dependency checker to resolve task resolution errors.

🎯 Why: Without keys, Compose uses item position for rendering. If the list order changes or items are inserted/removed, Compose is forced to recompose all items that shifted position, leading to jank and CPU spikes in dynamic lists. The CI fixes resolve configuration caching issues and task ambiguity with flavors.

📊 Impact: Prevents unnecessary recompositions of list items during Bluetooth scanning, fuzzing, and vulnerability discovery where lists update frequently. Reduces CPU usage during rapid list updates. Ensures the main integration pipeline is green.

🔬 Measurement: Verify by monitoring UI performance and recomposition counts in Android Studio Layout Inspector while discovering new devices or fuzz findings.
